# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| latest  | ✅        |

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

To report a security vulnerability, please send an e-mail to
[osrb-admins@hpe.com](mailto:osrb-admins@hpe.com) with the following information:

- A description of the vulnerability and its potential impact
- Steps to reproduce the issue or a proof-of-concept
- Any known mitigations or workarounds

You will receive an acknowledgement.

## Handling Policy

This project follows HPE's Open Source Software Security Review Policy and the
obligations imposed on Open Source Stewards under **Article 24 of the EU Cyber
Resilience Act (EU CRA)**, which requires that security stewards:

1. Maintain this documented cybersecurity policy.
2. Handle reported vulnerabilities in a defined and timely way.
3. Cooperate with EU market surveillance authorities on request.
4. Report actively exploited vulnerabilities to the relevant authorities where required.

## Disclosure Process

1. Reporter submits vulnerability details privately (see above).
2. Maintainer triages and confirms the issue.
3. A fix is developed and tested internally.
4. A patched release is published.
5. A public advisory is issued after users have had reasonable time to upgrade.
